# 视觉设计参考

## 通用优先级（固定不变）

1. 打印 / PDF 可靠性
2. 信息扫描效率
3. 中文长文阅读舒适度
4. 克制的装饰

> 四者冲突时，永远牺牲后面的。宁可朴素，不要牺牲分页与可读性。

## 文档类型自动判定

生成 HTML 前**自动判定**类型，**不向用户询问、不阻塞流程**，判定结果在交付说明中记录。
用户显式指定类型时以用户指定为准。

| 类型 | 判定线索 | 版式方向 |
|------|----------|----------|
| `project-proposal` | 标题含「方案 / 建议书 / 规划」；出现目标、范围、实施步骤、里程碑、资源、风险 | 稳重、清晰、适合评审；标题页安静留白 |
| `technical-tutorial` | 出现前置条件、步骤、命令、代码块、示例输出、故障排查 | 层级强、代码友好、命令与输出可区分 |
| `business-report` | 出现执行摘要、指标、结论、趋势、行动建议 | 正式克制、指标入表、结论突出但无营销装饰 |

判定不确定时按 `business-report` 处理，并在交付说明中标注「类型判定存疑」。

## 各类型语义映射

### 项目方案

- 背景 / 现状 → 普通章节 + 简短导语
- 项目目标 / 成功标准 → 摘要卡片或两列键值表
- 方案 / 实施路径 → 编号章节 + 步骤区块
- 里程碑 / 资源投入 → 表格
- 风险与对策 → 两列表格或简洁提示框
- 结论 / 下一步 → 收尾摘要卡片

**不要**把长篇论述拆成卡片 —— 卡片只用于短内容。

### 技术教程

- 前置条件、步骤、命令、示例、预期输出、警告、故障排查各自层级分明
- 代码块在屏幕上可横向滚动，打印时安全换行或收窄，不得溢出
- 命令与其输出视觉上必须可区分

### 商务报告

- 执行摘要置前
- 指标用真实 `<table>`，不用装饰性图形代替
- 结论突出但不使用营销式视觉
- 来源注释与假设保持可见

## 中文排版

- 字体回退链：`-apple-system`, `BlinkMacSystemFont`, `"PingFang SC"`, `"Hiragino Sans GB"`, `"Microsoft YaHei"`, sans-serif
- 实质中文段落用 `text-align: justify`；标题、短标签、表头保持左对齐
- 行距与行宽舒适，避免整页密排文字
- **禁止**依赖远程字体或 CDN
- 中文标点与原文措辞不得改动
