# 需求访谈纪律（model-interview / grilling）

围绕当前主题的每个方面持续访谈用户，直到双方达成共同理解。

## 四条纪律

1. **一次只问一个问题**，等回答后再继续。一次问多个问题会让人失去方向。
2. **每个问题附上你的推荐答案**（含理由与备选项），让用户做选择题而不是问答题；用户可以否掉推荐。
3. **事实与决策分离**：
   - *fact* 能通过探索环境找到的（文件、目录、`tlk tools search`、`tlk model dict`、`tlk model export`），直接查，不问用户；
   - *decision* 属于用户——逐个交给用户决定，并等待回答，不替用户拍板。
4. **共识达成前不采取行动**：沿着 decision tree 的每个分支往下走，逐一解决决策之间的依赖；用户确认「达成共同理解」之前，不开始实施。

## 沿 decision tree 走

- 先列出当前主题的待决策清单（脑内即可，不必先输出），按依赖关系排序：上层决策（范围/目标）→ 中层（结构/形态）→ 下层（实现细节）。
- 每得到一个答案，判断它是否改写了后续分支（用户的新信息常常收窄甚至取消某些问题），及时更新决策清单再问下一个。
- 用户补充的事实与既有认知冲突时，先核实（回环境查证），再修正决策清单——不要带着已证伪的前提继续问。

## 与 model-designer 的衔接

模型设计需求的访谈按 `model-designer/references/discovery.md` 执行：阶段 0 判定能力组 → L1 数据面 → L2 交互面 → L3 验收面，产出「模型任务书」并经用户确认后才生成 XML（任务书门禁）。本纪律是那套问卷的**执行方式**，问卷内容以 discovery.md 为准。

## 收敛标志

出现以下情形即可收尾，进入实施：
- 决策清单全部有归属（决定/明确排除/明确延后）；
- 剩余未知全部是可自行查证的事实；
- 用户对「我们达成了什么共识」的汇总没有异议。

实施前把共识落成文字（决策表/任务书/ADR），作为后续验收依据。
